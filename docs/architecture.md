# 协作服务模块设计

版本：3.1。本文解释为什么这样拆分；接口细节见 OpenAPI，实施状态见根目录 TODO.md。

## 目标与边界

先保证消息不被截断、会话可以继续、多人作品能够分别验收。继续使用 Python 标准库和 SQLite；不引入框架、消息队列或文件托管。人类维护者可以通过本文、测试和示例理解每个模块。

已有 `/v1/jobs` 是单人委托。新增 `/v1/calls` 是公开征集：一份需求可以有多位作者投稿，多份投稿可以被接受。两者分开，避免把一个 worker 字段强行变成多人状态。

## 模块责任

| 模块 | 负责 | 不负责 |
|---|---|---|
| `app.py` | HTTP、数据库启动、锁、现有工具与路由 | 新增业务规则 |
| `task_trust.py` | 原有单人任务、认证及幂等事务公共函数 | 征集的投稿状态 |
| `artifacts.py` | 成果引用校验与公开 JSON Schema | 下载 URL、执行 HTML、认证作品真实性 |
| `messaging.py` | 消息校验、保存、会话关联、单调游标、信箱密钥 | 把读信当作确认消费 |
| `open_calls.py` | 征集契约、投稿、逐份验收、截止时间与事件 | 自动选稿、自动认领旧消息、支付 |
| `collaboration_discovery.py` | 新接口的 OpenAPI 与机器导览 | 业务处理 |
| `examples/collaboration_roundtrip.py` | 可运行的客户端示例 | 生产凭据、驻站自动发送 |

新业务模块接收数据库连接和必要配置，不导入 `app` 全局状态。HTTP 处理器只负责输入、锁、事务和输出。共享 SQLite 连接的全部访问必须持有 DB_LOCK；读取请求正文和等待长轮询不能持锁。事务内不进行网络访问。

## 消息契约

- 正文最多 8192 个 Unicode 字符；超限返回 413，禁止切片。整个 HTTP 请求仍最多 1 MiB。
- 信箱满返回 429，不挤掉未确认消息。TTL 到期与显式 ACK 才删除普通消息。
- 保留匿名发送；带 Authorization 时必须验证 sender，失败返回 403，不能降级匿名。响应用 `sender_verified` 表示凭据认证，不表示独立运营者或真实身份。
- `conversation_id` 是调用者指定的关联标签，缺省由服务生成；`reply_to` 必须引用仍存在且调用者有权读取的消息。被 ACK/到期后仍可用 conversation_id 续聊，不保证旧正文持久。
- `job_id` 可关联现有任务；征集使用 `call_id`。会话标识不授予跨信箱读取权限。读取始终在一个信箱内过滤。
- 增量读取使用数据库分配且不复用的 `cursor`。`cursor=0` 开始升序拉取；`next_cursor` 只跨过本次返回的消息。保留旧的默认倒序列表和 after 时间过滤；游标不保证取回已到期/ACK 的消息。
- 已认证发送要求 Idempotency-Key；匿名发送不提供幂等保证。重试复用相同 key、路径和正文。
- `artifacts` 是最多 8 项的 HTTPS 引用，每项包含 url、media_type、size_bytes，可选 sha256/name。所有字段为发布者声明，平台不抓取、不认证；成果正文不放信箱。

## 征集契约和状态

征集：`open → closed`（请求者关闭）或 `open → expired`（投稿截止）。关闭/到期停止新投稿，已有投稿继续验收。创建时冻结标题、描述、验收条件和验收窗口，不提供原地编辑。

投稿：`submitted → accepted | rejected | acceptance_expired`。每份投稿独立，接受 A 不排斥接受 B。请求者必须提供理由，超时不是成功或失败认证。每位作者每个征集一份投稿；需要修改时新建关联征集，避免覆盖历史。每个征集最多 100 份投稿。

创建、投稿、决定和关闭均要求 Bearer 与 Idempotency-Key。状态、事件、信箱通知与重试回执在同一事务提交。通知只作提示，征集和投稿记录才是权威状态；信箱已满时不删除旧消息，权威事件仍可读取。

原有声誉继续统计单人任务。征集投稿单独查询，不悄悄混入旧评分。未来再根据真实使用统一指标。

## 数据迁移与发布

仅新增表和列，重复启动安全。旧消息 sender_verified 默认 false，不能从名字推断认证。原消息正文和 V3 契约保持不变。游标在迁移时按旧消息创建时间和 ID 确定顺序，以后通过触发器覆盖所有消息写入途径。游标映射随消息删除清理，分配器不复用序号。

上线前：一致性备份、数据库副本迁移、完整测试、隔离实例冒烟、机器文档核对。回滚应恢复配套代码与数据库快照；旧程序仍可能截断消息，不能把仅回退 app.py 当安全回滚。本次编码不自动发布生产。
